# Plan: Add per-run instance ID for multi-thread temp folders

Goal: Implement Option 1 so that each EMRALD run instance (within a single process) shares a unique runInstanceId across its threads, and use that ID to make per-thread temp folders unique per run while keeping intra-process threads coordinated.

## Scope
- SimulationDAL/EmraldModel.cs
- SimulationEngine/ProcessSimBatch.cs
- SimulationEngine/JSONRun.cs

## Steps

1. **Add runInstanceId field and property to EmraldModel**
   - Introduce a private field `string _runInstanceId = "";`.
   - Add a public property `RunInstanceId` with get/set.
   - Do not serialize this into model JSON; it is runtime-only.

2. **Update GetTempThreadFilesPath to include runInstanceId**
   - Modify `GetTempThreadFilesPath(int threadID = -1)` in EmraldModel to compute the temp path as:
     - Base: `%AppData%\\EMRALD\\<fileName>_<runInstanceId>_T<threadID>` when `RunInstanceId` is non-empty.
     - Fallback: existing `%AppData%\\EMRALD\\<fileName>_T<threadID>` when `RunInstanceId` is empty (backward-compatible).
   - Use `CommonFunctions.NormalizeCombine` as today.

3. **Add a runInstanceId field to ProcessSimBatch**
   - Add `private readonly string _runInstanceId;` to ProcessSimBatch.
   - In the constructor, assign `_runInstanceId` from a parameter `runInstanceId` rather than generating a GUID here.
   - Pass `_runInstanceId` into the EmraldModel before calling DeserializeJSON:
     ```csharp
     this._lists = new EmraldModel();
     this._lists.RunInstanceId = _runInstanceId;
     this._lists.DeserializeJSON(modelTxt, origionalRootPath, origionalFileName, threadNum);
     ```
   - Ensure this is done before any call to `GetTempThreadFilesPath` via `DeserializeJSON`.

4. **Generate and share runInstanceId in JSONRun per process/run**
   - In JSONRun (where `_simRuns` and threads are created), generate a single `runInstanceId` string once per run, e.g.:
     ```csharp
     string runInstanceId = Guid.NewGuid().ToString("N");
     ```
     or another deterministic scheme if desired.
   - Pass that `runInstanceId` into each ProcessSimBatch via an extended constructor:
     ```csharp
     _simRuns.Add(new ProcessSimBatch(_model, TimeSpan.Parse(options.runtime), options.resout, options.jsonRes, options.pathResultsInterval, runInstanceId, ConfigData.threads == null ? null : i));
     ```
   - Ensure the constructor signature in ProcessSimBatch is updated accordingly.
   - This guarantees all threads in one JSONRun invocation share the same runInstanceId, but different JSONRun invocations (even within the same process) get distinct IDs.

5. **Leave cleanup logic largely unchanged**
   - `ClearMultiThreadData` operates on `this.rootPath` and its parent directory; with runInstanceId included in the path, it will delete the correct per-run instance directory and older siblings.
   - Confirm that the parent directory remains `%AppData%\\EMRALD` or one level below it, so the "clear old thread files" logic still applies logically.

6. **Review for other EmraldModel instantiations**
   - Grep for `new EmraldModel()` and confirm that only the multi-thread run path (ProcessSimBatch) needs `RunInstanceId` set.
   - For single-threaded or UI uses that do not use multi-thread temp folders, it is safe to leave RunInstanceId unset (empty string), using the legacy path naming.

7. **Testing / validation**
   - Conceptually test:
     - Single EMRALD instance with multi-threading: folders under `%AppData%\\EMRALD\\<fileName>_<runInstanceId>_T0`, `_T1`, etc.
     - Two JSONRun invocations on the same model (either sequentially or concurrently): they should use different `runInstanceId`s and produce distinct folder trees.
     - Ensure that `ClearTempThreadData` per ProcessSimBatch clears only its own instance's folders.

Execution order:
1) Implement changes in EmraldModel (steps 1–2).
2) Update ProcessSimBatch constructor and RunBatch to accept and use runInstanceId (step 3).
3) Update JSONRun to generate and pass runInstanceId (step 4).
4) Re-check cleanup paths and any other callers (step 5–6).
